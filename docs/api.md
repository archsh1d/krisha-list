# API для интеграций

Локальный сервер предоставляет `/api/v1/status`, `/api/v1/listings`,
`/api/v1/listings/{id}`, `/api/v1/runs`, `/api/v1/runs/{id}` и синхронный
`POST /api/v1/collections`. Точная схема: [OpenAPI 3.1](../web/dist/openapi.json).

API предназначен для серверных клиентов. Bearer-токен генерирует и хранит
**оператор своего экземпляра**. `python scripts/init_env.py` создаёт токен для
Docker Compose; при запуске без Docker можно использовать `KRISHA_API_TOKEN`
или `--api-token-file`. Этот локальный токен не выдаётся Kolesa и не является
разрешением на сбор. Не отправляйте его в публичные репозитории и клиентский JS.

`POST /collections` требует включённого живого сбора и разрешения источника.
Запрос выполняется синхронно; длительный обход может превысить тайм-аут клиента.
После разрыва соединения состояние проверяйте через `/runs`. `max_pages=0`
означает проход доступной пагинации, но HTTP-отказ может остановить его раньше.
Результат со `cached=true` взят из предыдущего снимка, `pages=0` означает ноль
новых страниц. Проверяйте `cached_at`, `source_status`, `geo_errors` и историю
запусков.

`GET /listings` поддерживает фильтры категории, города, района, прямоугольника
и `updated_after`, а также `limit`/`offset`. При обновлении базы во время обхода
страницы с `offset` могут сместиться. Для согласованного экспорта остановите
сбор на время чтения или создайте резервную копию SQLite.

Текущая реализация использует **один токен на экземпляр** без ролей, срока
действия и отдельных квот. Не распространяйте его среди независимых
разработчиков. Публичный многопользовательский API требует отдельного
шлюза и управления доступом; см. [безопасность](../SECURITY.md).
