# Krisha List

**Язык:** **Русский** · [English](en/usage.md) · [Қазақша](kk/usage.md)

## Веб-интерфейс

Для самостоятельного развёртывания начните с [инструкции](deployment.md).
Локальный интерфейс читает каталог, историю цен и журнал сборов из SQLite, а
CSV формирует через локальный API. Для проверки импорта без запросов к Krisha.kz
используйте синтетический [HTML-файл](../web/dist/sample.html).

Если отдельно разместить `web/dist` как статическую страницу, она хранит
импортированные данные в браузере и показывает кнопку «Посмотреть на примере».
Кнопка «Собрать объявления» передаёт выбранные параметры в локальный сборщик;
на локальной странице пользователь нажимает её ещё раз для начала запроса.
В раскрывающемся блоке «Сбор запускается локально» можно указать порт своего
сервера. Статическая страница сама не запрашивает Krisha.kz.
Режим «Все страницы выдачи» идёт по ссылкам пагинации до их окончания и
сообщает, дошёл ли до последней страницы. При ошибке источника после нескольких
страниц результаты отмечаются как неполные. HTTP 468 со страницей проверки
SafeLine прерывает живой сбор; при наличии полного предыдущего снимка он явно
показывается как сохранённый.
Повтор с теми же параметрами в течение 15 минут использует свежий снимок без
нового обращения к сайту. После HTTP 403, 429, 468 или страницы проверки доступа
с кодом HTTP 200 действует общая пауза 30 минут. При повторных отказах она
увеличивается до 1, 2 и 4 часов; `Retry-After` может продлить её ещё больше.
Сервис показывает время следующей попытки и при наличии снимка
открывает его без нового запроса. Живой сбор выдерживает минимум 3 секунды
между завершением одного сетевого ответа и следующим запросом, включая карту.
После каждых шести запросов интервал увеличивается ступенями до 12 секунд.
После истечения 15 минут сервис вновь получает HTML, но в течение 6 часов
может использовать координаты карточек из полного снимка с теми же параметрами.
Это сокращает запросы карты; `reused_coordinates` показывает число таких карточек.
Это уменьшает частоту обращений, но не гарантирует устранение HTTP 468.
Каталог поддерживает дома, дачи и квартиры: фильтр категории помогает работать
с каждой выдачей отдельно. После живого сбора через локальный сервер карточки
также показывают координаты и ссылку на точку карты; в CSV есть отдельные поля
широты и долготы.
В блоке «Область» можно нарисовать полигон на большой карте или задать
прямоугольник четырьмя координатами. Отдельная кнопка «Нарисовать область на
карте» открывает редактор без раскрытия настроек. Для полигона нажмите
«Нарисовать заново», отметьте минимум три вершины и нажмите «Сохранить область».
Можно убрать последнюю вершину, очистить контур, перемещать и масштабировать
карту. «Отмена» и закрытие карты оставляют прежнюю область без изменений;
«Удалить область» подтверждает очистку. Выбранная область ограничивает живой
сбор, каталог и скачиваемый CSV; она сохраняется в браузере. Над таблицей
отдельно показаны последняя попытка сбора и текущая выборка с датой последнего
наблюдения. При активной области сводка также сообщает, сколько карточек во
всём каталоге не имеют координат и потому не могут быть проверены по контуру.
Для нового сбора выберите город и способ задания области: название района или
микрорайона либо полигон на карте. Подсказки по названию включают проверенные
разделы Krisha.kz и адреса сохранённых карточек. Для проверенных разделов
запрашивается выдача выбранной местности. Произвольное название проверяется
по адресам карточек, полученных из выдачи города: при ограничении числа
страниц часть объектов может не попасть в результат. Выберите «Все страницы»
для обхода доступной пагинации; отказ источника может прервать и этот обход.
Выбранный способ также ограничивает показ каталога, сводку, карту и CSV.
При активной области локальный сервер запрашивает выдачу по всему Алматы с
охватывающим прямоугольником, а затем оставляет только точки внутри точного
контура. Карточки без координат в выбранную область не входят. Для ручного
прямоугольника порядок полей: северная широта, западная долгота, южная широта,
восточная долгота.
Опубликованная версия сама не обращается к Krisha.kz. Локальная версия хранит
рабочие данные в SQLite. Импорт HTML в локальном интерфейсе также пишет в базу.

Для живой отладки при наличии разрешения Kolesa запустите локальный сервер из
каталога проекта:

```powershell
.venv\Scripts\python -m krisha_list serve --enable-live --db data/krisha.sqlite3
```

Затем перейдите на `http://127.0.0.1:8765/`. В панели «Автоматический сбор с Krisha.kz» выберите
«Дома и дачи» или «Квартиры» и соберите одну или до десяти страниц выдачи
Алмалинского района. Для фильтров цены, комнат и других параметров можно
вставить ссылку на соответствующую выдачу Krisha.kz в поле «Ссылка на выдачу с
фильтрами»; она имеет приоритет над выбранной категорией. При выборе области
без собственной ссылки поиск идёт по всему Алматы. Сервер доступен
только на локальном компьютере. Он сохраняет объявления и координаты карты в
SQLite, а HTML и JSON каждой полученной страницы — в `data/snapshots/`.
При первом открытии локальная версия переносит ранее сохранённые в этом
браузере реальные карточки в SQLite, не затирая более свежие записи базы.
Журнал содержит параметры живых запусков, число страниц и объектов, исключения по
области, HTTP-статус и причину остановки. «Полный» означает, что пагинация
закончилась; «Ограничен страницами» и «Прерван» не означают полной выдачи.
Повторный HTTP 468 записывается с нулём новых страниц и датой использованного
снимка. Показы снимка без сетевого запроса в журнал не добавляются. Сводка
показывает дату последней фиксации данных.

Для домов «цена объекта / сот.» означает цену всего дома с участком, делённую
на площадь участка, а не отдельную оценку земли. Группы менее пяти объектов
показываются без медианы.

## API для разработчиков

Версионированный серверный JSON API доступен на локальном Python-сервере по
`/api/v1`. В комплекте есть [краткое руководство](../web/dist/api.html)
и [OpenAPI 3.1](../web/dist/openapi.json),
но не публикует каталог SQLite и не запускает сбор. Для данных нужен ваш
запущенный экземпляр сервиса.

Создайте токен один раз и запустите сервер с ним:

```powershell
.venv\Scripts\python -c "import secrets; from pathlib import Path; Path('data/api-token.txt').write_text(secrets.token_urlsafe(32), encoding='utf-8')"
.venv\Scripts\python -m krisha_list serve --enable-live --api-token-file data/api-token.txt
```

Вместо файла можно задать переменную окружения `KRISHA_API_TOKEN` длиной не
менее 32 символов. Не добавляйте токен в URL, JavaScript браузера или Git.
API принимает `Authorization: Bearer <token>` и отклоняет запросы с заголовком
`Origin`; обращайтесь к нему из серверной части интеграции. Для доступа по сети
можно указать `--host 0.0.0.0`, но при этом токен обязателен; используйте
HTTPS-прокси. Старый интерфейс и его маршруты остаются доступны только с
локального компьютера.

Маршруты: `GET /api/v1/status`, `GET /api/v1/listings`,
`GET /api/v1/listings/{id}`, `GET /api/v1/runs`, `GET /api/v1/runs/{id}`,
`POST /api/v1/collections`, `GET /api/v1/openapi.json` (спецификация без токена).
Список карточек поддерживает `category`, точные `city` и `district`, `bounds`
(север, запад, юг, восток), `updated_after` (ISO 8601 с часовым поясом),
`limit` (1–100) и `offset`. Ответ содержит `data`, общее число `page.total`
и `page.next_offset`. Отдельная карточка также содержит историю цены.
При параллельном обновлении каталога состав страниц с `offset` может меняться;
для согласованной выгрузки не запускайте новый сбор во время обхода.

`POST /api/v1/collections` принимает те же `url`, `max_pages`, `bounds`,
`polygon` и `location_query`, что локальный сборщик. Запрос синхронный: клиент
должен дождаться завершения или после разрыва связи проверить `GET /api/v1/runs`.
Паузы, повторное использование снимков, защита от параллельных запусков и
остановка при HTTP 468 действуют и через API. Для этого маршрута нужен
`--enable-live` и разрешение владельца источника.

Пример чтения первых 50 домов через PowerShell:

```powershell
$token = (Get-Content data/api-token.txt -Raw).Trim()
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/api/v1/listings?category=house&limit=50' -Headers @{ Authorization = "Bearer $token" }
```

## Консольный инструмент

Локальный сборщик **HTML-списков продажи домов, дач и квартир** на Krisha.kz. Он читает
только основную выдачу, отделённую от блока «Горячие предложения», и сохраняет
объекты по ID в SQLite. Повторный проход обновляет карточку и добавляет событие
в историю, если изменилась цена.

Для каждой страницы выдачи сборщик запрашивает соответствующий JSON бокового
списка карты и связывает координаты с карточками строго по ID. Если позиции
выдачи и карты сдвинулись, дополнительно проверяется следующая страница карты.
Поля `latitude`,
`longitude`, `geo_source`, `geo_zoom`, `geo_type` добавлены в таблицу `listings`
и в экспорт. `geo_source=krisha_map_list` означает позицию, показанную самим
сайтом; `geo_source=krisha_map_list_cached` означает точку из снимка не старше
6 часов. Позиция не обязательно указывает на точный участок или вход в дом. Если
карта не вернула координаты, поля остаются пустыми. При повторном сборе ранее
полученные координаты сохраняются, если новый ответ карты временно пуст.

Проект не открывает страницы отдельных объявлений, не получает контакты и не
обходит защитные проверки сайта. Если разметка списка изменилась или сайт
вернул страницу защиты, сбор останавливается с ошибкой.

## Установка

Python 3.11 или новее. В PowerShell из каталога проекта:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e .
.venv\Scripts\python -m krisha_list --help
```

## Использование

Для проверки на **локально сохранённой** странице:

```powershell
.venv\Scripts\python -m krisha_list parse-file page.html
.venv\Scripts\python -m krisha_list stats
.venv\Scripts\python -m krisha_list export --output listings.csv
.venv\Scripts\python -m krisha_list export --table price_history --format jsonl --output prices.jsonl
```

Если файл соответствует другой странице выдачи, передайте её адрес через
`--url`; он нужен для корректной пагинации и определения номера страницы.

При наличии письменного разрешения владельца сайта на автоматический доступ:

```powershell
.venv\Scripts\python -m krisha_list collect
.venv\Scripts\python -m krisha_list collect --url "https://krisha.kz/prodazha/doma-dachi/almaty-almalinskij/" --max-pages 2 --db data/krisha.sqlite3
.venv\Scripts\python -m krisha_list collect --url "https://krisha.kz/prodazha/kvartiry/almaty-almalinskij/" --max-pages 2 --db data/krisha.sqlite3
.venv\Scripts\python -m krisha_list export --db data/krisha.sqlite3 --category apartment --output apartments.csv
.venv\Scripts\python -m krisha_list collect --max-pages 1 --db data/probe.sqlite3 --snapshot-dir data/snapshots/probe
```

Для ограничения территории передайте `--bounds` в формате
`север,запад,юг,восток` (широта и долгота в десятичных градусах):

```powershell
.venv\Scripts\python -m krisha_list collect --url "https://krisha.kz/prodazha/doma-dachi/almaty-almalinskij/" --bounds "43.255,76.87,43.24,76.91" --max-pages 2 --db data/krisha.sqlite3
.venv\Scripts\python -m krisha_list export --db data/krisha.sqlite3 --bounds "43.255,76.87,43.24,76.91" --output area.csv
```

`collect` передаёт границы в выдачу Krisha.kz, а затем проверяет координаты
каждой карточки перед сохранением. Объявления без точки карты и точки за
пределами прямоугольника исключаются. Если `bounds` уже есть в `--url`, он
тоже учитывается. `export --bounds` фильтрует существующую базу и совместим с
`--category`. При сборе по области `--no-geo` недоступен. Координата карты
может быть приблизительной, поэтому граница относится к показанной на карте
точке, а не к юридическим границам участка.

Без `--max-pages` команда следует по ссылке «Дальше» до конца списка. Между
запросами по умолчанию выдерживается пауза от 3 до 12 секунд по мере прохода.
Команда учитывает ту же
паузу после отказов, которая сохранена в SQLite. Ответы HTTP 403/429/468
останавливают сбор. Если Krisha.kz возвращает страницу проверки SafeLine,
локальный API сообщает об этом и сохраняет `source-error.json` со статусом и
адресом запроса, а также `source-response.html` для диагностики. CLI сохраняет
`source-error.json`, если указан `--snapshot-dir`.
Прокси и обход защит в проект не включены.
Параметр `--snapshot-dir` сохраняет полученный HTML до разбора карточек и JSON
ответа карты. При необходимости `--no-geo` отключает запросы к карте. Ошибка
карты отражается в `geo_errors` итогового JSON, а сбор HTML продолжается.

## Данные

`listings` содержит ID, каноническую ссылку `/a/show/<id>`, заголовок, тип
объекта, категорию, комнаты, цену в тенге, район, адрес, координаты позиции на
карте, краткое описание, тип продавца, город и дату в том виде, как она показана
на сайте. Для домов есть площадь дома и участка; для квартир — площадь квартиры,
этаж, этажность здания и жилой комплекс, если они указаны. Год постройки
извлекается из превью при наличии.

`price_history` хранит первоначальную цену и последующие изменения с временем
наблюдения в UTC. `first_seen_at` и `last_seen_at` относятся к наблюдениям
сборщика, а не к моменту публикации объявления. Дата на карточке часто не
содержит года; она сохраняется как исходная строка. Пустые поля в HTML
остаются пустыми в базе. Удаление объекта с сайта не определяется по одному
неполному проходу.

CSV и JSONL экспортируют только локальную базу и не делают сетевых запросов.

## Проверка

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
```

Автоматические тесты используют небольшой искусственный HTML-образец. Отдельный
[отчёт живой проверки](live-test-2026-11-14.md) описывает проход по реальной
выдаче 14 ноября 2026 года. Изменение сайта может потребовать обновить парсер.
Повторный живой прогон с координатами собрал 133 из 133 точек на семи страницах.
Проверка квартир на первой странице получила 23 карточки, из них 20 с точками
карты. Число объявлений на сайте меняется, а рекламные карточки могут не иметь
соответствия в боковом списке карты.

## Доступ к данным

[Пользовательское соглашение Krisha.kz](https://krisha.kz/content/special/agreement)
требует письменного разрешения Kolesa для автоматического доступа и извлечения
объявлений. Команду `collect` следует использовать только после получения
такого разрешения. Локальный `parse-file` позволяет проверить структуру
имеющегося HTML без обращения к сайту.
